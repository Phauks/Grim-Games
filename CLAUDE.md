# Working on Grim-Games

- Read `README.md` for the stack, layout and commands.
- `src/lib/core` is pure TypeScript: no Svelte, SvelteKit, DOM or UI imports (ESLint enforces it). Game logic goes there with Vitest tests.
- Features never import `@ark-ui/*`; they use our wrappers in `src/lib/ui/primitives`.
- Before building a control, layout or helper, check `docs/shared-components.md`: the same feature in two places is one shared component (Trevor). Extend the shared one rather than copy it; lint lists named `*_TODO` only shrink.
- Use the game's own terminology (character type vs alignment, seat, reminder, Fabled/Loric as rule characters). Don't invent terms.
- The BotC wiki is the rules authority. Tests for characters and jinxes cite the wiki page they encode; paraphrase, never copy wiki prose (it has no licence).
- Character rules are data (Trevor, 2026-10-22): one rules block per character, in `src/lib/core/data/rules/<id>.json` for official characters or `rules` in a custom character's script entry. A new entry for a moved table goes in that file, never in a TypeScript table; rules code names no character. The moved and not-yet-moved tables are listed in `docs/shared-components.md`.
- Exception (Trevor, 2026-10-15): the glossary popover shows the wiki Glossary's exact wording, fetched live from the wiki API and cached on the device only (`src/lib/features/glossary/wiki-glossary.svelte.ts`). The same holds for a character's whole wiki page in the character dialog (`src/lib/features/characters/wiki-page.svelte.ts`, Trevor 2026-10-16). Never bundle either in the repo. Revisit before any public launch.
- Clean-room rewrite: never copy code from Pocket Grimoire (GPL-3.0) or other GPL projects.
- A setting beside a Settings preview (Board, Tokens) must change that preview, or be disabled while its effect is off; `e2e/setting-previews.e2e.ts` fails otherwise (Trevor, 2026-10-22).
- Every screen has a way back (Trevor, 2026-10-26): the hamburger, or a game or start-flow screen's own Back (`SetupNav`); the browser's or phone's back never counts. Mark the control `data-way-back`; `e2e/way-back.e2e.ts` opens every route and fails on a new route it doesn't list. Deliberate dead ends (locked draw PIN, a forced choice) stay dialogs over a screen that has one.
- Touch first: tap targets of at least 44px, Pointer Events, and every new flow gets a Playwright test on the phone and tablet projects.
- No fixed pixel sizes in styles (Trevor, 2026-10-16): layout uses `var(--u)` and the tokens, text uses rem/em, space-filling uses % or viewport units. `npm run lint:px` enforces it; a px that must stay says why in a `/* px-ok: ... */` comment on the same line.
- When a feature works differently, or not at all, on Android, iOS or desktop, add or update its row in the platform gaps list, `/mnt/project-files/platform-gaps.md` (Trevor, 2026-10-20): what was checked, or the doc it rests on, and any fallback the app shows.
- Imports inside `src` use `#lib/...` with the `.ts` extension for TypeScript files.
- The Roadmap page ticks itself off: a PR title names the roadmap IDs it finishes in brackets, such as "Savant info generator (L2)", and a new plan ID goes in `src/lib/features/about/roadmap.ts` as a part of the feature it belongs to (or a new feature). The roadmap lists features, not bug fixes or polish. The Changelog lists every merged PR by title, so titles are written for people using the app.
- Before pushing: `npm run verify` (check, lint, unit tests; the pre-push hook runs it) and the e2e tests you touched. Changes reach `beta` through a PR with green CI; turn on auto-merge so it lands when the checks pass.
- Worker logs keep query strings (`redact_query_string: false` in wrangler.jsonc). Never put private game state, room secrets or scripts in a query string; use the path or the URL hash (the hash never reaches the server).
- All work goes on the `beta` branch (Trevor, 2026-10-15); it deploys as the `beta` Worker Preview. `main` is production and only receives releases from `beta`.
- The app is an offline-first PWA (`src/service-worker.ts`): each build is precached and only replaces the old one when the user taps Refresh. Saved game state must therefore be versioned with migrations, because a newer build can open a game saved by an older one.
- **No layout reflow (Trevor).** Don't add information or fields unless needed. Anything that may appear later is rendered in place but disabled (or reserved space), or not at all if hiding it causes no reflow. Extra detail goes in a modal, sheet or toast overlay, never expanded inline.
